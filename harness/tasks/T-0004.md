# T-0004 — Air Quality Fetching & Geocoding (`src/lib/aqi.ts`)
Backlog ref: T-0004 · Sprint: 1 · Priority: MUST

## Intent
Fetch live ambient PM2.5 and AQI for the user's location using Google Air Quality API as primary, with seamless fallback to keyless Open-Meteo API, backed by a 10-minute cache and medical warning classification for severe smog (AQI ≥ 300).

## Scope / Out of scope
- **Scope**:
  - `src/lib/aqi.ts`: Geocoding (Open-Meteo geocoder with built-in major city coordinates), Google AQ API client, Open-Meteo fallback client, in-memory 10-minute TTL cache (up to 200 entries), AQI category and warning generator (severe/hazardous AQI ≥ 300 banner).
  - Dependency injection of `fetch` for 100% hermetic unit testing.
- **Out of scope**: UI components (T-0007).

## Requirements
- REQ-001: Live AQI from Google AQ API with Open-Meteo fallback.
- REQ-007: Graceful degradation on failure (`AQI_UNAVAILABLE`).
- REQ-014: AQI ≥ 300 escalation banner.

## Acceptance
- AC-001-a: Given a valid city/location, returns current AQI & PM2.5.
- AC-001-b: Given Google AQ API unavailable, falls back to Open-Meteo and flags source.
- AC-001-c: Given lat/long coordinates, skips geocoding and fetches AQI directly.
- AC-007-c: Given both sources fail, throws/returns `AQI_UNAVAILABLE`.
- AC-014-a: Given AQI ≥ 300, marks `isSevereHazard = true` and generates medical care advice.
