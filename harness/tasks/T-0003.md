# T-0003 — Input Sanitisation & Rate Limiting (`src/lib/sanitize.ts`, `src/lib/rate-limiter.ts`)
Backlog ref: T-0003 · Sprint: 1 · Priority: MUST

## Intent
Defend against prompt injection, denial of service, memory exhaustion, and invalid API keys before making any expensive or network-bound calls.

## Scope / Out of scope
- **Scope**:
  - `src/lib/sanitize.ts`: Key format validator (`x-gemini-key`), payload size guard (8 KB), free-text sanitizer (strip control chars, HTML/script markup, cap at 300 chars, preserve Unicode), profile validator.
  - `src/lib/rate-limiter.ts`: 8 req/min sliding window memory limiter with bounded cache (5000 max entries) and automatic cleanup.
- **Out of scope**: Next.js route handling (T-0006).

## Requirements
- REQ-002: User submits household form.
- REQ-008: Gemini key validation (`NO_KEY`, `BAD_KEY`).
- REQ-009: 8 req/min/IP rate limiting, 8 KB body cap.

## Acceptance
- AC-007-a: Given no/malformed Gemini key, When verified, Then code `NO_KEY` or `BAD_KEY` is flagged before network calls.
- AC-009-a: Given 9 requests in 1 minute from one IP, When the 9th arrives, Then rate limiter rejects with remaining=0.
- AC-009-b: Given a request body > 8 KB, When checked, Then rejected as oversized.
